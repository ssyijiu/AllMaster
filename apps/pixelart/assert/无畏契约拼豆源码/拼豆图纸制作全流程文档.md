# 无畏契约拼豆图纸制作全流程文档

> 本文档讲清一件事：一张可以实际施工的拼豆图纸，是怎么从一张参考图一步步变成 36~156 格色号矩阵和可交互图纸页的。

---

## 一、整体流程（五步）

```
参考图 ──→ 读图定看点 ──→ AI 生成像素底稿 ──→ 确定性转色号矩阵 ──→ 渲染交互图纸页
```

### 第 1 步：确定主体与参考图

- 玩家上传的图是**默认唯一视觉参考**，不自动混入其他素材。
- 没有图时，按创作目标去找参考：官方立绘、游戏截图、经核实的梗图画面。
- 主体分两类：
  - **character / character-prop**：人物、英雄、角色带道具（如捷风 + 手枪）
  - **prop**：武器皮肤、挂饰、物品、风景（如暴徒本体、隐世修所挂饰）

### 第 2 步：读图，找到"看点"

生图之前先回答一个问题：**这张图为什么好看或有趣？**

- 可能是低模建模的纸片脸 + 呆眼（搞笑向）
- 可能是皮肤的本体结构、光效轮廓（还原向）
- 可能是某个手势、神态、配色组合

这个看点会被写进提示词最优先保住的位置，交付时也会跟玩家确认："我把重点放在 XX 上，这是你想要的点吗？"

### 第 3 步：AI 生成平面像素底稿

以参考图为唯一视觉输入，生成一张：

- **1024 × 1024，PNG，透明背景**
- **纯 2D 平面像素画**：硬边纯色色块
- **没有**：渐变、阴影、网格线、豆孔、塑料珠质感、摄影光影
- 颜色数量克制，色块清晰，方便下一步映射到拼豆色卡

底稿只是中间产物，不是交付物——真正交付的是第 5 步的图纸 HTML。

### 第 4 步：确定性转色号矩阵

底稿生成后，用一个**确定性的转换脚本**（非 AI，结果可复现）把底稿处理成五档规格的色号矩阵：

| 档位 | 适用构图 |
|------|----------|
| 36×36 | 只适合头部为主体的大头特写 |
| 52×52 | 半身像起步 |
| 78×78 | 全身像（含 Q 版全身）起步 |
| 104×104 | 全身且头部占比小的立绘 |
| 156×156 | 长版 / 细节最多的上限档 |

关键点：

- 每一颗豆的颜色都映射到 **MARD 221 色卡**（palette_mard221.csv）里**最接近的实际色号**，不是随便的颜色——你买得到对应的豆子。
- 玩家指定板子尺寸（如"52 的板"）时，默认展示那一档，并附相邻档参考；没指定就五档全出，页面上可自由切换。
- 尺寸越小，色块合并越严重、细节损失越多，所以交付前有一道**尺寸核验**：检查每档里眼睛朝向、表情、耳朵轮廓、嘴和描边是否可辨，以此决定推荐哪一档，页面上打"推荐"标签。

### 第 5 步：渲染交互图纸页（最终交付物）

产出**单文件 HTML**，命名格式 `【拼豆专家】任务名-M月D日_H点M分S秒.html`，页面里可以：

- 切换 36 / 52 / 78 / 104 / 156 五档规格
- 查看每格色号、每种颜色的用量统计
- 在线改颜色（映射到色卡内换色）
- 导出图纸，方便照着施工

## 二、提示词是怎么拼出来的

一段完整的生图提示词 = **固定底座 + 四个可变模块 + 画风段**。

### 固定底座（每次都有，讲清拼豆工艺约束）

- 告诉生图模型：这是一张**拼豆图纸的底稿**，不是插画
- 平面像素画、硬边纯色、透明背景、无渐变无阴影无网格无豆孔
- 色块大小、颜色克制的具体要求

### 四个可变模块

| 模块 | 内容 | 什么时候填 |
|------|------|-----------|
| **角色背景** | 官方设定里的外观配色、技能画面形态、社区梗 | 做英雄/皮肤时，来自已核实的资料；查不到就留空，不编造 |
| **主体描述** | 这张图里主体长什么样：发型、服装、武器、颜色 | 每次 |
| **画面分析** | 对参考图的读图结论：保住什么、舍掉什么 | 图生图时 |
| **构图** | 动作、姿势、取景、头身比、画面方向 | 每次 |

### 画风段

按画风库选择（贴纸、柔彩手绘、还原……），每种画风有自己的适用对象和取舍规则；库中没有的可以现写定义。

> **色卡约束不靠提示词**：MARD 色卡由下游转换脚本硬性完成，不会把色卡图片喂给生图模型。

## 三、一份完整示例提示词

以「Q 版贤者 · 贴纸画风 · 治愈手势」为例，下面是拼好后实际发给生图模型的完整文本（图生图模式，配贤者官方立绘作参考图）：

```
【任务】
把参考图中的角色转化为一张适合拼豆施工的平面像素画底稿。

【拼豆工艺要求】
- 输出为纯 2D 平面像素画：硬边纯色色块，色块之间无渐变过渡
- 透明背景，只画主体本身，不画任何背景元素
- 禁止出现：阴影、光照、网格线、豆孔、塑料珠质感、摄影质感、3D 渲染感
- 颜色总数克制（约 12~18 色），每种颜色区域足够大、边界清晰，
  保证缩小后每个色块仍能对应到至少一颗拼豆
- 关键五官（眼睛、嘴）和轮廓描边即使在小米数下也要保持可辨

【角色背景】
贤者（Sage）是《无畏契约》中的中国守护者英雄，治疗与复活能力者。
外观特征：黑色长发束起，服装以白、玉青、金三色为主，
带有东方玉器与书法元素，施法时周身浮现青绿色能量。

【主体描述】
Q 版贤者，二头身比例，头大身小。
黑色长发束成高马尾，白色衣袍配玉青色饰边与金色纹样。
面部为简洁的 Q 版表情，大而明亮的眼睛，带温和的微笑。

【画面分析】
参考图为贤者官方立绘。重点保留：白玉青金的配色体系、
高马尾轮廓、东方服饰纹样的简化形态、温和的神态。
舍弃：立绘的复杂褶皱光影、背景与特效细节，
技能能量效果简化为胸前一小团青绿色光点色块。

【构图】
半身居中构图，微微侧身面向观者，
双手在胸前合拢、掌心向上，托起一团青绿色治愈能量。
头部占画面高度约二分之一，底部留出少许透明边距。

【画风：贴纸】
整体轮廓加一圈白色描边，形似贴纸的裁切边缘；
色块饱满、边界利落，圆润的 Q 版体态，
保留少量装饰细节但不追求写实。
```

文生图（不带参考图）时，去掉【画面分析】模块，其余结构相同——但必须先经玩家同意，因为只靠文字，造型和配色可能不如照着图画得准。

## 四、改图的两条路

改图分两种情况，处理方式完全不同：

### 路线 A：底稿被认可后，只改局部（换色 / 加配件 / 改表情）

- 直接以**已认可的底稿**为唯一输入图
- 修改要求写到部位和结果，例如："斗篷和兜帽从紫色改成红色"
- 附上玩家认可底稿的原话作为确认依据
- 姿势、构图不动

### 路线 B：换姿势 / 换画风 / 换构图 / 没认可上一版

- 必须回到**真实参考图**重画（玩家原图 > 官方立绘 > 重新找图）
- 换画风 = 重画时替换画风段，其他模块照旧
- 之前生成的底稿、图纸预览**不能**当作重画的参考图——每轮生图都会丢细节，拿 AI 产物当参考会越改越偏

## 五、常用参数速查

| 项目 | 默认值 |
|------|--------|
| 底稿尺寸 | 1024 × 1024 |
| 格式 | PNG，透明背景 |
| 色卡 | MARD 221 色 |
| 规格档位 | 36 / 52 / 78 / 104 / 156 |
| 玩家指定尺寸 | 默认展示该档 + 相邻档参考 |
| 交付物 | 单文件交互 HTML 图纸页 |

## 六、一张好图纸的判断标准

1. **看点保住了**：这张图最有趣/最好看的特质在像素稿里仍然成立
2. **五官可辨**：核验档位里眼睛朝向、表情、耳朵轮廓、嘴和描边都看得清
3. **色块能拼**：每个色区对应得到真实豆子色号，没有碎成噪点的区域
4. **舍得不心疼**：小尺寸下被舍弃的细节，是本来就表达不出来的，不是关键信息
