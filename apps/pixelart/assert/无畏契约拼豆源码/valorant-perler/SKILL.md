# 拼豆图纸生成

## 目标

输入已确定的作品主体、一张参考图或玩家同意的文生图方案，以及画风要求，先生成一张适合算法处理的平面像素底稿，再由确定性脚本切成多规格豆位矩阵，最终交付 `output/` 下带时间戳的图纸页（`【拼豆专家】{任务名}-{M月D日}_{H点M分S秒}.html`）。

中间底稿不是图纸。只有像素底稿、色号矩阵、多规格总览和 HTML 全部生成，任务才完成。

## 工作目录

每次任务使用独立且可指定的绝对路径，建在本次对话的工作区目录下（例如 `workspace/` 里新建一个子目录）。`.codebuddy` 下的目录（插件、技能目录与缓存）不放工作目录：App 端从那里读不到产物，图纸和样例都展示不出来。

```text
<work_dir>/
├── .wip/
│   ├── 原图/原图.<原后缀>
│   ├── 提示词/提示词配置.json、提示词.md
│   ├── 转换图/转换图.png、转换图_去贴纸边.png（去掉贴纸白边后的切格输入）
│   ├── 过程文件/{36,52,78,104,156}_k28/
│   ├── 评审/尺寸对比.png
│   └── 运行记录.json
└── output/
    └── 【拼豆专家】{任务名}-{M月D日}_{H点M分S秒}.html
```

工作目录由你自己记录，不向玩家展示路径。下载参考图、写配置与日志、生成底稿和 CSV 时，全部放在该目录的 `.wip/`；`output/` 只放那一个图纸 HTML。WorkBuddy 产物区会预览工作目录下的所有文件，工作目录根下与 `output/` 里不要另写任何文件。提示词的可变内容使用中文。HTML 内联图片、色号矩阵与统计数据，玩家只转发 HTML 就能打开，Excel 在页内按需导出。脚本默认清理 `.wip/过程文件/` 过程文件（WorkBuddy 产物区会预览所有文件）；需保留时加 `--keep-process`。

## 输入契约

作品主体由玩家需求或专家与玩家确认的创作方案给定。参考图使用玩家上传或专家取得并经玩家确认的图片；画风采用玩家指定或认可的方案，未指定时使用「还原」。

**单视觉参考**：本次确认的图片是唯一视觉参考。生图的参考图只用 `.wip/原图/原图.<原后缀>`。

先看原图；明显有与作品无关的多余元素时（如截图状态栏、互动栏或大片留白），先裁切，保留完整主体。处理好的图存到 `.wip/原图/原图.<原后缀>`，用于后续生图、尺寸对比与页面「原图」页签；拿不准时保留原图。

MARD 色号由 prompt 中的颜色约束和下游 `scripts/palette_mard221.csv` 映射实现。生图时不传色卡图片、拼豆成品案例、历史效果图、角色图库或卡面。

玩家提到角色、技能、梗、配色或电竞信息，或读图时这些细节不确定，加载 `无畏契约知识检索` 按其流程查询。查知识、生图、掌瓦登录都走本技能的 `scripts/val_perler.py`（查知识是 `search` 子命令）；知识整理后写入 `game_knowledge`，不替代视觉参考。用户未提供图片时，通过 `无畏契约素材取图` 选择一张贴合本次创作需求并经确认的真实参考图；采用文生图时按「文生图（须玩家同意）」执行。开场随机两路的参考图确认例外按专家说明执行。

## 阶段 01：组装提示词

读 `image_prompts/像素图生成.md`，按它为这张图写四个可变 slot（`game_knowledge`、`subject_description`、`image_analysis`、`composition`），保存到 `.wip/提示词/提示词配置.json`，再用 `--prompt-only` 拼出 `.wip/提示词/提示词.md` 通读检查。

固定 slot `image_prompts/01-base_specs/task_mission.md`、`pixel_style.md` 由一键脚本自动拼在最前面，负责讲清拼豆是什么、像素化要求和透明背景，可变 slot 不重写它们。视觉色块供下游采样，不是最终豆位。

人像模板与 `--art-style` 的选择、默认造型、比例、取景及复制话术按 `image_prompts/03-art_style/README.md` 和 `像素图生成.md`「选画风」执行。每次生成、复用底稿或修改图纸前，先根据参考图与玩家描述判断主体并显式传入 `--subject`：真人照片、人物和机器人角色用 `character`，人物或角色为主体且带道具可用 `character-prop`，武器、挂饰、物品、风景等其他主体用 `prop`，无法确定时用 `prop`，玩家可更正。其他主体默认还原或接受玩家自定义描述；只有人物或角色展示可选模板与画风示意，其他主体隐藏整个示意区。未指定模板默认还原。实际模板记在 `.wip/运行记录.json` 的 `art_style`；自定义、局部修改和修复后的图不标预设模板。模板卡展示同一张参考图的效果示意，点击复制提示词，返回对话后以玩家要求和分类重新创作。

### 角色动作

玩家要换动作、手势、神态、比例或取景时，读 `image_prompts/像素图生成.md`「角色动作与模板定制」。

### 柔彩手绘：画风与动作分开

保持柔彩手绘的低饱和配色、深灰线条和像素平涂画法；动作、姿势、表情、手势及构图按玩家本次要求定制。参考图用于确认角色身份、发型、配色和配饰，玩家指定新动作时，以新动作覆盖参考图姿势，写进 `subject_description` 与 `composition`，并在 `image_analysis` 区分保留的辨识点和要改变的动作。哭哭大头是可选主体模板，按新动作调整其中的小手、道具与取景，不作为动作限制。

换动作、姿势或构图时，沿用 `--art-style 柔彩手绘`，按阶段 01 使用真实参考图重画；只有已认可底稿的局部调整才走 `--edit`。未指定新动作时沿用参考图。

## 阶段 02 至 04：一键完成

运行前根据玩家目标和画面主体拟一个简短、自然、可辨识的任务名。任务名描述作品本身，不包含 `CASE`、版本、算法、色板或减色参数。

默认直接运行：

```bash
python3 scripts/val_perler.py generate .wip/原图/原图.png \
  --work-dir <work_dir> \
  --prompt .wip/提示词/提示词配置.json \
  --task-name "<WorkBuddy 拟定的本次任务名>"
```

本次指定或确认了画风时加 `--art-style <画风>`（见阶段 01）。

选默认尺寸时按专家的“推荐尺寸”章节，根据最终构图和关键细节核验，生成命令加 `--default-size <边长>`；`--target-size` 只用于玩家明确指定的板尺寸。交付前读取 `.wip/评审/尺寸对比.png`，推荐与页面默认打开尺寸保持一致。需要升档而 `.wip/过程文件/` 已清理时，沿用同一任务的原输入、配置和任务名，追加 `--skip-gen --effect-image <work_dir>/.wip/转换图/转换图.png --default-size <边长>` 重跑一键命令；玩家指定过尺寸时保留原 `--target-size`。这条路径复用底稿，不重新生图。

玩家明确指定了板子尺寸时加 `--target-size <边长>`（15–156）：默认展示这一档；边长小于 52 时只附 52 作参考，52 及以上附上下相邻的固定档（如 52 → 36/52/78）；边长不超过 52 时提示词自动拼入 `target_size` 段（`image_prompts/01-base_specs/target_size.md`），让底稿按这块小板子的粒度画、轮廓优先。玩家要长方形 W×H 时按长边 `max(W,H)` 传 `--target-size`，见下方「长方形请求」。玩家没说尺寸时不加，照常出五档；36 或 52 缺陷严重、难以局部修复时，用 `--boards` 列出其余档位重跑，不渲染这一档。

**长方形请求**：图纸只有方板，玩家要 W×H 的长方形时不拒绝，按长边出方板（`--target-size` 取较大值，超过 156 取 156）。图案本身是横幅或竖幅时（玩家要的长方形、横放的枪、竖幅立绘），生图加 `--render-size 1536x1024`（横）或 `--render-size 1024x1536`（竖），`composition` 写「横向撑满画布」或「竖向撑满画布」，图案就按这个比例画满。切格时脚本按图案外接框把它居中放回方板，不拉伸，不需要另做转换。生成后多出来的空格子留空，交付时告诉玩家不用拼。

底稿最外圈如果是一圈白色贴纸边、里面才是图案描边，脚本默认先把白边去掉再切格，图纸外圈就不会多出一圈白豆，描边也能按里面那圈深色补齐。没检出白边时底稿原样使用，检测结果记在 `.wip/运行记录.json` 的 `sticker_border`。玩家明确要保留白边（例如就想要贴纸那圈白边框）时加 `--keep-sticker-border` 重跑，跳过这一步。

该命令完成以下产物：

1. 渲染服务生成唯一底稿 `.wip/转换图/转换图.png`。
2. `alignment_search.py` 从同一底稿生成五档（36/52/78/104/156）矩阵。
3. `build_html_blueprint.py` 生成 `output/【拼豆专家】{任务名}-{M月D日}_{H点M分S秒}.html`，标题使用任务名，副标题使用实际 HTML 渲染时间。页面是「顶栏 → 图纸 → 编辑栏」的三站流，手机和电脑同一套；编辑栏顶部是三站 Tab，栏上的小箭头把手收起 / 展开，宽屏下栏可放在底部、左侧或右侧：「1 规格调整」选拼豆板尺寸，下面是默认收起的「颜色数量」与「色号规格」（色板）；「2 图纸编辑」用画笔 / 填充 / 橡皮 / 取色 / 移动逐格改，面板里有图纸在用的「颜色」和「孤立像素」；「3 辅助拼豆」是照着下豆的沉浸站（画布上不响应进编辑手势，要改图回 02 站），内容是两列的拼豆进度记录表：顶部是完成百分比与已拼颗数，上方灰底提示卡说明用法（可关闭，本机记住）；点色块在图纸上高亮这一色对照下豆，下完点右边方框打勾，表头右侧总勾选框可全选 / 全不选；底部大按钮「导出图纸」打开导出抽屉。站点可以随时跳，切站不改变编辑栏的收起状态，三站的栏高一致。图纸上方切「平面 / 3D」（3D 可模拟烫豆），顶栏「导出」从底部升起分享图编辑器：下载一张带色号用量统计与二维码的 PNG 海报（方豆 / 圆豆、色号、网格线、发光、原图与烫后小图、底色、清晰度可调，手机上长按保存）。恢复初始图纸在「版本」里。触屏下单指拖动平移、双指缩放、点格子看色号、长按格子进入编辑。页面数据带底稿颜色簇与每格票数 + 25 套色板，玩家切色板、调颜色数量时浏览器现场落色。与主体不相连、面积不到主体 10% 的小块（气泡、爱心、特效）默认剔除，玩家在「图纸编辑」站的「孤立像素」里可以逐块或全部恢复、再移除。玩家要五档以外的尺寸时，在「规格调整」站「拼豆板尺寸」下填一个方形板边长（15–156 格），输入框右侧即时回显「×N」，页面用同一套对齐搜索现场算出新规格卡（数秒，自定义是上限、不保证铺满）；Agent 不需要为自定义尺寸重跑脚本。页面是单文件，数据、three.js 和图片都内联在里面。
4. `make_overview.py` 生成 `.wip/评审/尺寸对比.png`，两列等宽卡片排列，五档规格加原图为 2×3；只供 AI 核验默认展示尺寸，不发给玩家。
5. 生图提示词留在 `.wip/提示词/提示词.md`，运行状态与最终路径写入 `.wip/运行记录.json`，输出列表中 HTML 位于首位。
6. 默认清理 `.wip/过程文件/`，底稿 `转换图.png` 保留。加 `--keep-process` 可跳过清理。

脚本运行时会打印以「进度 · 」开头的行，写给玩家看，语气轻松，只讲在做什么、要等多久。等待期间向玩家转述进度就用这几行的意思，不转述方括号阶段行、路径、命令、参数和算法名。命令同步执行，跑完才返回——大板通常四五十秒完成，等待期间把脚本打印的进度行转述给玩家即可。

### 修改玩家已认可的底稿

只有玩家明确认可过的底稿才能修改，且只改局部（颜色、配件、表情、删元素），姿势和构图不动。玩家没认可、或要换姿势/动作/构图/画风时，按阶段 01 重画：参考图用真实的非 AI 图片（玩家本次上传的图 → 上一轮新建用过的 `.wip/原图/原图.*` → 按 `无畏契约素材取图` 找到的真实参考图），新要求写进四个可变 slot；本专家生成过的底稿不作为重画参考。

```bash
python3 scripts/val_perler.py generate <玩家已认可的底稿> \
  --work-dir <新的 work_dir> \
  --edit "<修改要求，或 .md/.txt 文件路径>" \
  --confirmed "<玩家认可这张底稿的原话>" \
  --task-name "<修改后画面的任务名>"
```

`--edit` 的内容具体到部位和结果（“斗篷和兜帽从紫色改成红色”），玩家点名要保留的也写进去，不重复拼豆画风规则，这些由固定 slot 负责。

`--edit` 不带 `--confirmed` 时脚本以非零状态退出，改走真实参考图重画。认可原话另存为 `.wip/提示词/confirmation.md`，并写进 `.wip/运行记录.json` 的 `confirmed_by_user`。

提示词拼装顺序为 `task_mission` → `pixel_style` → `edit_mission` → `edit_request`：前两段保证拼豆画风不丢，`edit_mission`（`image_prompts/01-base_specs/edit_mission.md`）要求只改被点名的部分、其余色块与构图保持原样，`edit_request` 是用户这次的修改内容。修改模式不补 `subject_description`，因为主体就是参考图本身。需要额外背景时仍可用 `--prompt` 传 JSON slot（如 `game_knowledge`），它们排在 `edit_request` 之前。修改要求原文另存为 `.wip/提示词/edit_request.md`，`.wip/运行记录.json` 的 `mode` 为 `edit`。

用户明确要求先审底稿时，可先加 `--prompt-only` 检查提示词，或仅运行生图阶段；获得确认后用 `--skip-gen --effect-image <已确认底稿>` 跑完整交付链。其他请求不在底稿阶段停下。

## 引擎

`generate` 调用团队渲染服务生成底稿：提交图片和提示词，每 5 秒轮询，成功后下载透明 PNG。服务地址是 `https://val-perler.qq.com`。固定参数为：

- 质量：`low`
- 背景：`transparent`
- 格式：`png`
- 尺寸：`1024x1024`

一键脚本已经固化以上参数，常规任务直接运行，也不需要凭据。没有用户图片时，默认先找一张确认过的角色参考图走图生图；服务也支持文生图，但只在下面「文生图」一节的条件下用。

### 文生图（须玩家同意）

没有参考图、文字直接生图，只在两件事都成立时用：

1. 未找到合适的参考图，或玩家选择了适合文字生成的原创方案（例如自己编的组合、换装、结合预设画风与角色背景设计的动作）。普通原创表现无需为了找同姿势图片反复搜索；角色外观与背景按需核实。玩家指向具体梗、名场面或特定作品时，先按专家「输入纪律」与 `无畏契约素材取图` 核实对应视觉内容，文字生成不能代替这一步；找不到时请玩家提供参考，或明确征得同意后改做新的原创设计。
2. 玩家明确同意了文字生图。

先问玩家，不自行文生图。问的时候说明本次缺少合适参考或准备采用原创文字方案，问能不能直接按文字描述画，并用一句话说明原因：只靠文字描述，角色的造型和配色可能不如照着图画准，所以先跟他确认；同时给 2 到 3 个描述方案让玩家选，每个方案写明画风（从 `image_prompts/03-art_style/README.md` 的画风里选）和动作或姿势，例如「A：Q 版，盘腿坐着比耶；B：贴纸，只留头和肩膀，歪头笑；C：还原，站姿持刀」。玩家也可以自己改方案。

玩家同意并选好方案后，不传位置参数，把玩家同意的原话写进 `--t2i-confirmed`：

```bash
python3 scripts/val_perler.py generate \
  --work-dir <work_dir> \
  --prompt .wip/提示词/提示词配置.json \
  --task-name "<任务名>" \
  --t2i-confirmed "<玩家同意文字生图的原话>"
```

选中方案的画风写进 `--art-style`，动作写进 `subject_description` 与 `composition`。角色外观只靠文字，`game_knowledge` 写进查到的外观、配色、标志性配件。不带 `--t2i-confirmed` 时，没有参考图的生成会直接退出。图纸页没有「原图」页签。

修改已有底稿走上面的 `--edit`，与新建使用同一个服务和参数。

生图失败时脚本以非零状态退出，错误里写明失败步骤（提交、轮询、取图）和服务返回的原文，原样报告给用户。后台繁忙例外：报错里有 `error_code=rate_limited`，或 HTTP 429，服务原文给出前面的排队人数，或说繁忙、排队时间过长、请求太频繁、额度用完，或轮询超时没等到结果，不把原文报告给玩家，按下面「后台繁忙时」处理。

### WorkBuddy ID

每个生图请求（提交、查询、取图）的请求头都带玩家的 WorkBuddy ID（`X-WB-Id`），脚本自己取，玩家无感。取值顺序：环境变量 `ACC_USER_ID`，个人配置目录名，本地缓存 `~/.config/valorant-perler/credentials.json`（`PERLER_CONFIG_DIR` 可改目录）。读到前两者就刷新缓存。`python3 scripts/val_perler.py render --check-id` 只检查、不生图，打印来源与脱敏后的 ID。

三处都没有时，脚本在发请求之前以非零状态退出，提示指向本节。这时由你去找：

1. 环境变量：`echo "$ACC_USER_ID"`（Windows：`echo %ACC_USER_ID%`）。
2. 个人配置目录：Mac 和 Linux 运行 `ls ~/.workbuddy`，Windows 运行 `dir %USERPROFILE%\.workbuddy`；找名为 `user-<ID>-personal` 的目录，`<ID>` 是目录名里的 UUID（形如 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`，其中 x 为十六进制字符）。有多个时取最近修改的；设了 `WORKBUDDY_CONFIG_DIR` 就看它指向的目录。
3. 找到后运行 `python3 scripts/val_perler.py render --set-id <ID>` 保存，再重新生图。

ID 只认标准 UUID，`--set-id` 会拒绝其他内容。昵称是手机号，任何情况下都不读、不传、不存、不写进回复。

找不到 ID 时，不提 ID，问玩家要不要先用 WorkBuddy 自带的生图工具画这张；同意了按「改用 WorkBuddy 自带生图」做。

### 后台繁忙时

先读报错里的服务原文。原文给了明确的建议（继续等、多久后重试、建议换一种方式等），按它做，下面三步只在原文没给建议时用。原文里的模型名、配额、等待上限这类内部诊断信息只给你判断用，不转述给玩家：
- 让等或让稍后重试：照它说的时长等，再用同一份提示词重新运行；跟玩家用自己的话说明要等一会儿、大概多久，不贴原文。
- 建议换一种方式：换成它说的方式。要换成 WorkBuddy 自带生图时，照样先问玩家，同意后才用。
- 原文和下面的登录引导不冲突时，两者都做。

1. 看脚本日志：写着「匿名模式」说明没登录。先引导玩家登录掌瓦（见下「掌瓦登录」），告诉他登录后走登录用户的生图额度，排队更短；登录成功后用同一份提示词重新运行一键脚本。
2. 已经登录仍繁忙，或玩家这次不想登录，原样用这句问玩家：「当前服务时间繁忙，拼豆搭子正在努力使用后台服务画图，但需要等待较长时间，是否我先切换为WorkBuddy自带生图工具给你先看看效果？」
3. 玩家同意，按「改用 WorkBuddy 自带生图」做；玩家想等，隔一会儿用同一份提示词重新运行。

### 改用 WorkBuddy 自带生图

玩家同意改用 WorkBuddy 自带的生图工具（工具区里的 ImageGen，与 bash 等工具并列）之后才用它，没问过或玩家没同意都不用；图生图和文生图都一样。用它文生图时，同样先按「文生图」一节给玩家选画风和动作方案。用它画底稿，其余步骤不变；交付时如实告诉玩家这次底稿用的是 WorkBuddy 自带的生图工具，话术见专家提示词「交付时怎么说」。

1. 提示词用本次任务的 `.wip/提示词/提示词.md`，参考图用 `.wip/原图/原图.*`。
2. 画好的图存为 `.wip/转换图/转换图.png`。
3. 运行 `val_perler.py generate <原输入> --work-dir <同一个 work_dir> --prompt <原 --prompt> --task-name <同一任务名> --skip-gen --effect-image .wip/转换图/转换图.png`，其余与默认闭环一致。修改模式不能带 `--skip-gen`，这一步去掉 `--edit` 和 `--confirmed`，`--prompt` 改给 `.wip/提示词/提示词.md`。

### 掌瓦登录

`python3 scripts/val_perler.py login` 让玩家用掌瓦 App 扫码，登录凭据存进本机 `credentials.json`，之后每次生图自动带上（走登录用户的生图额度）。本机已有有效登录时直接返回，不重复扫码。命令运行期间会在本机弹出二维码图片，同时打印图片路径和扫码链接，最多等 5 分钟；玩家扫码授权后命令才结束。换账号用 `login --force`，退出用 `logout`；扫码失败、玩家另有凭据时用 `login --set-auth-key <值>` 手动写入。

### 连通性测试

玩家想确认生图服务能不能用时，在 skill 目录运行 `python3 scripts/val_perler.py render --health`。它只请求服务的 `/health`（`https://val-perler.qq.com/health`），不需要图片和提示词，也不会开始生图、不写 `output/`。把 HTTP 状态和服务返回原文告诉玩家；200 说明服务可达，不代表一次完整生图已验证。

同一区域出现近色交错、条纹或花斑时，交给 `拼豆图纸修复` 做交错色检查；`--merge-close-colors` 默认关闭。

## 完成判据

逐项检查：

- 底稿是平面像素画，没有实体豆孔和摄影质感。
- 默认已清理 `.wip/过程文件/`；加 `--keep-process` 时过程文件保留。
- `output/【拼豆专家】{任务名}-{M月D日}_{H点M分S秒}.html` 存在且是单文件（不外链 `data.js`、`vendor/`），任务名和 HTML 渲染时间正确。
- `.wip/评审/尺寸对比.png` 可读取，已确认默认展示尺寸。
- `.wip/运行记录.json` 的 `status` 为 `completed`，且输出列表中 HTML 位于首位。
- `output/` 里只有这一个图纸 HTML。

任一检查失败时停在失败阶段并报告真实错误。
