# 像素图生成

先读参考图和本次确定的主体、画风及构图要求，再为这张图填写 `提示词配置.json`。`scripts/val_perler.py generate` 负责加载提示词文件，按固定顺序拼成生图提示词。

## 提示词放在哪里

按适用范围从基础要求到特定场景排列；编号用于阅读导航，实际 slot 拼接顺序见下一节。以下路径相对于 `image_prompts/`：

- `01-base_specs/`：拼豆基础规格——任务目标、像素色块画法、透明背景、小板尺寸、局部修改要求，以及拼豆品牌色号参考。
- `02-game_knowledge/`：游戏知识怎样约束生图的典型案例（名字歧义改色、梗图保留、技能动作重建）。知识本身每次按这张图用 `valorant-knowledge` 现查，不从这里取。
- `03-art_style/`：人像模板——还原、像素大头、贴纸、手绘头像、Q版、柔彩手绘，以及自定义画法。模板画法在 `art_style.md`，默认造型在 `subject_description.md`，取景在 `composition.md` 或本次构图。
- `04-subject_description/`：主体描述——人物与道具的默认模板（脚本缺省加载），以及整幅还原、保梗描图、主次比例等写法。
- `05-composition/`：构图——半脸竖条、竖版画布等版式写法。
- `06-image_analysis/`：原图取舍——去文字、换姿势保角色、核心元素提取等写法。

## 脚本怎样拼接

### 新建图稿

专家在 `提示词配置.json` 中填写四个描述段落（XML slot）：`game_knowledge`、`subject_description`、`image_analysis`、`composition`。脚本补齐基础规格并加载画风，按下表顺序拼接；JSON 中的书写顺序不影响结果。

| 顺序 | slot | 加载内容 |
|---|---|---|
| 1 | `task_mission` | `01-base_specs/task_mission.md`：拼豆任务、豆板与实体色；柔彩手绘、像素大头小图、手绘头像新建任务不补此段，拼豆要求由 `pixel_style` 承担 |
| 2 | `pixel_style` | `01-base_specs/pixel_style.md`：像素色块、硬边与透明背景；画风目录自带 `pixel_style.md` 时改用它（像素大头小图的 24 至 28 列大色块，手绘头像的底稿段） |
| 3 | `target_size` | 仅指定 `--target-size` 且边长 ≤ 52 时，加载 `01-base_specs/target_size.md`，填入本次尺寸 |
| 4 | `art_style` | 根据 `--art-style` 加载 `03-art_style/<画风>/art_style.md`；未指定时用还原；自定义描述填入 `03-art_style/custom.md` |
| 5 | `game_knowledge` | 专家填写：这是谁、有什么辨识点 |
| 6 | `subject_description` | 专家填写：画成什么样；未填写时按下面的主体描述规则补齐 |
| 7 | `image_analysis` | 专家填写：参考图保留什么、舍弃什么 |
| 8 | `composition` | 专家填写：主体怎样放进画布 |

主体描述优先采用专家填写的内容。未填写时，人像使用所选模板目录里的 `subject_description.md`；该文件不存在时用 `04-subject_description/subject_description.md`。手绘小人等叫法按Q版目录加载。非人像（`--subject prop`）使用 `04-subject_description/subject_description_prop.md`。模板有 `composition.md` 且本次未填写构图时加载它；显式主体或构图整段优先。

基础规格负责拼豆与像素画法，画风负责线条、五官画法和上色，比例与动作写在主体描述，取景写在构图。专家填写的四段只描述这张图独有的内容。运行 `--prompt-only` 后，通读 `.wip/提示词/提示词.md`，确认各段要求一致，再正式生图。

### 角色动作与模板定制

玩家要换动作、手势、神态、比例或取景时，用真实角色参考图新建图稿，按下表填写四段。参考图提供身份；玩家没提新动作时，沿用参考图的动作。

| 段落 | 写什么 |
|---|---|
| `game_knowledge` | 角色身份与外观锚点，技能或梗的事实依据 |
| `subject_description` | 最终造型：头身比例、身体朝向、手脚位置、手持物、视线和眉眼嘴的状态 |
| `image_analysis` | 参考图保留的辨识点；原图哪些姿势、道具、特效被替换 |
| `composition` | 半身或全身、主体位置、必须完整入画的肢体和手持物 |

默认比例和动作写在模板目录的 `subject_description.md`，取景写在 `composition.md` 或本次构图。填写 `subject_description` 会整段替换这份默认描述：先读它，保留玩家没改的比例和身份处理，再写入新动作。玩家要全身盘腿时采用Q版，主体写完整比例和盘腿动作，构图写头脚完整入画。

贴纸和像素大头小图只画固定造型。玩家点了这两种又要全身动作时，说明固定取景装不下该动作，推荐用Q版承载完整身体动作。

道具任务的 `subject_description` 只写轮廓和部件，不写动作。

动作要在 78 格里认得出：手和脸之间、交叉的手臂和衣服之间留出描边或色差；竖起的手指、细长手持物至少两格宽。`--prompt-only` 后检查三处：`subject_description` 写了新动作，其他段没有要求保留原姿势，构图装得下整个动作。

例如，同一张立绘改成指尖嘘声的手绘头像（运行时用 `--art-style 手绘头像`）：

```json
{
  "game_knowledge": "人物是参考图中的角色；保留浅紫白长发、紫色发梢、紫眼和左眼下小痣。",
  "subject_description": "胸上大头，头连头发占画面高度六成以上，脖子短、肩臂简化。一只手竖起食指轻抵唇前，另一只手落在胸前；头略低，眼睛眯起，嘴角是神秘的笑。食指画成连续宽色块，与脸部清楚分开。",
  "image_analysis": "参考图只提供身份、发型、配色与标志配饰。原图举手握光的姿势替换为本次嘘声手势，原光带与场景特效不画。",
  "composition": "胸上大头头像居中，头顶、肩部、唇前手指及胸前另一只手完整入画；人物以外透明。"
}
```

### 局部修改

`--edit` 使用已认可的底稿，按 `task_mission` → `pixel_style` → `edit_mission` → `edit_request` 拼接。前两段沿用基础规格，`edit_mission` 来自 `01-base_specs/edit_mission.md`，`edit_request` 是玩家本次修改原话。画风和主体沿用输入图；切换画风另建图稿。

## 选画风

画风选项采用玩家指定或认可的方案，通过 `--art-style` 传入生图流程。未指定画风时，缺省该参数，系统默认匹配「还原」：保持参考图原有画法和体态，归并细碎光影；人像必要时轻微放大头部以使五官可辨。

| 画风要求 | `--art-style` 传参 |
|---|---|
| 未提风格；“照着画”“保留原样” | 缺省不填 |
| “Q版”“萌化”“做成大头”“可爱风” | `Q版` |
| “贴纸”“头像”“做个小人”“整套英雄”，且不在意原姿态 | `贴纸` |
| “柔彩手绘”“粉彩手绘”“低饱和彩铅” | `柔彩手绘` |
| “像素大头”“大头小图”“像素头像”“大头加小手” | `像素大头小图` |
| “手绘头像”“手绘大头”“表情包头像” | `手绘头像` |
| “手绘小人”“简笔小人”“手绘表情包” | `Q版` |
| 自主描述非常规画风 | 按 `03-art_style/画风定义.md` 扩写后的画风描述 |

- 明确点了柔彩手绘时，优先选它而不是泛称的 Q 版或贴纸；读取 `03-art_style/misty-pencil/README.md`，按其中的定制项填角色、表情与构图。哭哭大头只是可选主体模板，不是通用风格。
- 明确点了像素大头小图时，读取 `03-art_style/pixel-big-head/README.md`，运行命令加 `--boards 36 52 78`，并按其中的定制项逐图填头型、颜色与配饰；只用于人物。
- 贴纸画风仅抓取角色辨识点，丢弃持枪、战术姿态及粒子光效；需要还原动作特征时统一选用 Q 版。角色任务未填 `subject_description` 时，脚本自动载入贴纸专用主体描述。
- 人像才使用预设模板，包括真人、人物和机器人角色。非人像用 `--subject prop`，默认还原，或接受玩家自定义描述；页面提供「是否人像」更正分类。适用范围见 `03-art_style/README.md`。
- 玩家描述了库里没有的画风，或你拿不准某种画风该长什么样时，读 `03-art_style/画风定义.md`，把玩家的说法扩写成具体的画风描述再传入。
- 选用还原以外的画风时，`image_analysis` 仅写动作取舍与部件剔除逻辑，严禁写入“比例完全对齐原图”等写实保真限制，防止风格冲突覆盖。
- 修改模式（`--edit`）禁止变更画风；切换画风必须另建新任务重绘。

## 流程

1. 看图，按下面的写法写四个可变 slot，保存为 `<work_dir>/.wip/提示词/提示词配置.json`。
2. 用 `--prompt-only` 拼出整段提示词并通读：

   ```bash
   python3 scripts/val_perler.py generate <用户原图> --work-dir <work_dir> \
     --prompt <work_dir>/.wip/提示词/提示词配置.json \
     --task-name "<本次任务名>" --prompt-only
   ```

   检查 `<work_dir>/.wip/提示词/提示词.md`：完整 `pixel_style` 与所选 `art_style` 已加载，可变段没有重复基础规则或矛盾的画法要求。柔彩手绘不应带默认的“选饱和”要求，角色发型、颜色归属与构图应是本张图的描述。
3. 去掉 `--prompt-only` 正常运行一键脚本。

## 每个可变 slot 怎么写

### `game_knowledge`：这是谁

写角色名（中英文）、定位，和 3–5 个辨识锚点：发型发色、脸型、服装主色、标志性配件。原图是社区梗图时写一句梗的内容，梗的气质要靠它传到画面里。有容易被误读的地方就先说明事实，例如“角色是素颜，脸上没有任何妆容”，模型就不会把光影画成眼影。

### `subject_description`：画成什么样

按部件写颜色归属：头发、皮肤、衣服、手套各是哪一块颜色，相邻的深色部件怎样区分（“深蓝紧身衣与黑色手套要有明度差”）。浅色部件写出色彩倾向，让它和透明背景下的白豆区分：银白发偏冷，肤色偏暖。

阴影写归属：脸上的暗部属于暖肤色加深一阶，眼周的暗部是刘海投影。这样写比“不要阴影”更有效，模型不会多加一套冷色阴影层。

五官写结果：眼睛大到缩成 52 格还能看出朝向，表情写成一句话（“自信的歪嘴笑”），嘴用比肤色深一度的单一颜色。按部件和结果去约束，比逐条列出画法禁令颜色更少、形态更自然。

道具写结构：外轮廓、部件连接关系，细长结构加粗到至少 2 格宽，花纹简化为几块色区，小零件并入相邻大块。

### `image_analysis`：原图取舍

沿用原动作时，先写必须保留的动作或手势及其位置（“左手在右下角比 V，戴黑色露指手套，必须完整保留”），再逐项写要去掉的东西：背景、特效、悬浮物、倒影、水印、头像气泡、签名。最后写原图画幅（“竖幅，约 437×595”），给 `composition` 做依据。

原图有多个变体（双配色、多个角色）时，明确指定取哪一个，例如“只画左侧金白配色那把枪，不混入右侧红黑配色”。写“任选一个”会让模型把两者混在一起。

### `composition`：怎么放进方形画布

画布默认是 1024×1024 正方形。玩家要长方形图纸，或主体本身明显是横幅 / 竖幅时，运行加 `--render-size 1536x1024`（横）或 `1024x1536`（竖），构图照下面写「横向 / 竖向撑满画布」；切格时脚本会把图案居中放回方板。按主体朝向写：

- 竖幅人物：保持竖幅比例，竖向撑满画布，左右自然留空；写明头顶、手势、脚底都完整入画，不拉宽、不裁切。
- 横向道具：水平横放，轴线与画布水平中线重合，左右撑到约 85%，上下留空。
- 胸像：胸像居中偏上，完整呈现头部、手势与肩部。

主体以外保持透明。

## 固定层已经负责的，不要再写

- 网格数和格子大小：模型不服从“144×144 隐含网格”这类精确数字，豆位数由下游脚本搜索。
- 网格线：画出的假网格尺寸与豆板对不上，会干扰对齐，成图变脏。
- 色卡参考图：生图只传用户原图一张，提示词里写“参考第二张色卡”会让模型去找不存在的图。
- 背景颜色：固定层和生图参数都是透明背景，可变段写“纯白背景”会和它冲突。
