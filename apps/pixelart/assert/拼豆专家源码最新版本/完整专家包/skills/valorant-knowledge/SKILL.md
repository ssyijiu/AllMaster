# 无畏契约知识检索

本技能只提供**检索流程与参数文档**，不含代码。执行检索的 CLI 在 `拼豆图纸生成` 技能的
`scripts/val_perler.py` 的 `search` 子命令（同一个 CLI 也负责生图和掌瓦登录）：需要查知识时，
打开本文件看流程和参数，然后到 `valorant-perler` 技能目录执行下面的命令。

## 目标

本技能负责有依据的文字信息：理解对象、技能设定、外观特征、社区梗与人物关系。联网是文字知识缺口的 fallback。图片定位、下载与视觉款式核对由 `无畏契约素材取图` 完成；玩家只要图片且对象清楚时，直接调用该技能。

资料内容分 12 个域：英雄（29 位特工 + 1 位即将上线，含外观、技能、人物关系等）、武器（21 类武器及其全部皮肤）、地图（13 张）、玩法、活动、赛事与电竞（赛事、战队、选手）、收藏（卡面、喷漆、挂饰、称号等）、联名、版本、音乐、游戏梗（约 1900 条）、其他（游戏概览、世界观）。拼豆工艺、绘制教程不在库内。

查到（或联网搜到）的结果，整理为可直接注入拼豆管线 `game_knowledge` slot 的文本：角色名、定位、标志性技能的视觉特征、常见社区梗的含义与视觉表达建议。

## 整理结果的边界

- 只写检索或搜索结果里有出处的内容。库里和网上都没有靠得住的说法，就当作不确定，`game_knowledge` 里对应部分留空，不用常识或印象补全特征、技能描述、配色。
- 检索或搜索结果里涉及涉黄、低俗或其他不当的内容，整理时直接略过，不写进 `game_knowledge`，也不在回答中提及。

## 先分清：端游还是手游

资料分两套，**互不混查**：`pc` = 无畏契约端游（默认），`mb` = 手游（《无畏契约：源能行动》，玩家常说「手瓦」「手游」）。同一个英雄在两端的设定、外观、技能可能不同，查错一套会拿到另一个游戏的内容。

- **看玩家说的是哪个**：明确指手游、手瓦、移动端、源能行动 → 手游；外形描述中的「手机」不单独决定平台；提到端游、电脑、PC，或没提 → 端游。拿不准而又影响结果时，直接问玩家一句「你说的是端游还是手游」。
- **命令里指定**：`query`、`list`、`get` 都支持 `--platform pc|mb`。`query` 不传时会按问句自动判断（问句里有「手游/手瓦…」就查手游，否则端游），结果里的 `platform` 字段告诉你实际查了哪一套。
- **后续命令要和刚才的 `query` 用同一套**：`get`、`list` 不传默认查端游，所以手游的编号（如 `英雄/捷风/外观`）必须带 `--platform mb`，否则会取到端游的同名页。
- **对比类问题**（「端游和手游的捷风有什么区别」）：两套各查一次，`--platform pc` 和 `--platform mb` 分别执行。
- 环境变量 `VAL_PLATFORM=pc|mb` 可设默认值。
- 一套里查不到，而玩家说的可能是另一端时，`next` 会提示换一端再查。

手游资料：11 个域（英雄、武器、地图、玩法、活动、赛事与电竞、收藏、联名、版本、游戏梗、其他），约 1150 篇；比端游少武器皮肤和音乐。

## 命令入口

所有操作走这一个 CLI。**必须先 `cd` 到 `valorant-perler` 技能目录再执行，或者把 `scripts/val_perler.py` 写成绝对路径**——你的当前目录通常是任务的 `work_dir`，直接写相对路径会报 `can't open file`：

```bash
cd <valorant-perler 技能目录> && python3 scripts/val_perler.py search <子命令> [参数]
# 或：python3 <valorant-perler 技能目录>/scripts/val_perler.py search <子命令> [参数]
```

| 子命令 | 作用 | 关键参数 |
|---|---|---|
| `query` | 按检索语句找资料（纯语义召回） | `检索语句`（位置参数）、`-q 另一条`（可重复，多条并发后合并去重）、`--platform pc\|mb`、`--filter 维度=值`（手动限定范围，一般不用）、`--pretty` |
| `list` | 列出有哪些 | `路径`（如 `英雄`、`英雄/捷风`，留空列顶层）、`--part 名称`（跨父节点取同名部分，如全部外观页）、`--match 正则`、`--offset N`（每页固定 30 条）、`--platform pc\|mb` |
| `get` | 按编号或路径取整篇全文 | `id或路径`（如 `英雄/捷风/外观`）、`--platform pc\|mb`、`--pretty` |
| `alias` | 查玩家的叫法是什么 | `叫法`（如 `奶妈`；留空列出全部对照） |
| `guard` | 发回复给玩家前的出口检查 | `--text 草稿` 或 `--file 文件` |

输出均为 JSON（`--pretty` 缩进）。退出码：0 成功；1 出错（含暂时不可用，**不代表没有这条**）；2 guard 拦截。

## query 的输出契约

**纯语义召回，不替你做决定**：不自动限定范围、不按置信度砍结果，每次返回前 3 / 10 / 20，每条都带置信度。读哪篇、够不够用、要不要联网，由你看了摘要和清单自己判断。无 top-k 参数。

| 字段 | 内容 |
|---|---|
| `text` | 前 3 篇**整篇原文**（不截断，长文切片全量拼回），含编号与置信度 |
| `summary` | 前 10 篇的编号 + 摘要 + 置信度 |
| `ids` | 前 20 个条目编号（多个 `-q` 合并后按编号去重） |
| `found` | 召回了几篇；`0` = 没有召回 |
| `platform` | 实际查的是 `pc` 还是 `mb` |
| `queries` / `scope` | 实际执行的检索语句（保留玩家原话）/ 手动 `--filter` 的范围（不传则为空） |
| `next` | 仅在没召回或最高置信度偏低（< 0.4）时出现：下一步该做什么 |

- **置信度只是参考，不是门槛**：同一篇在不同问法下分数差别很大（范围越大分数越低），0.45 的结果完全可能就是答案。看摘要对不对得上，对得上就用。
- 同一个名字可能对应多个条目（如「大明星」既是游戏梗，又是一场活动；英雄名同时有英雄页和梗页）：看摘要判断玩家指的是哪个，必要时两个都读。
- 前 3 篇原文里没有你要的，先看 `summary` 和 `ids` 里有没有，有就 `get` 那一篇。
- 明确问的是别的游戏（原神、王者荣耀……）且没提无畏契约，直接返回空。
- 没召回时看 `next`：要的是「一批」（合照、所有英雄、10 个英雄）→ 用 `list --part` 取全集，**不要联网**；否则换正式名重查或 `list --match` 核对，仍没有才联网。

编号就是知识路径（`英雄/捷风/外观`），可直接喂给 `get`。

## 检索流程：两轮，找不到再走联网

**查询要快**：一次只问一个问题，串行进行；一个问题查一次就够，别对同一问题重复查，也别一次连发多条。第二轮只对确实需要的实体 `list`/`get`。

**第一轮：`query`**（带 `--platform` 或让它按问句判断）
- 返回前 3 篇整篇原文、前 10 条摘要、前 20 个编号，每条带置信度。先看摘要和编号，判断方向对不对、前 3 篇够不够用。
- 够了就停，不再多查。

**第二轮：看相关实体还有哪些叶子，决定要不要补**
1. 从第一轮结果里挑出和玩家问题相关的实体（某个英雄、某张地图、某个赛事、某类武器）。
2. `list <域>/<实体>` 看它下面有哪些叶子（如 `list 英雄/捷风` → 外观、技能、人物关系…），**自己判断**还缺不缺别的叶子。
3. 缺的就 `get` 对应编号，取回来的**和第一轮的内容一起用**（找到的都要加入）。
4. 要的是一批（合照、所有英雄）：`list <域> --part <叶子名>` 列全集，挑要用的再逐个 `get`。
5. 怀疑有但没查到：`list --match 关键词` 按名称找；同名条目（梗/活动/英雄）看摘要分辨。

**两轮之后仍没有需要的信息**：按下节「库里没有时：联网补充」去网上搜。判断「没有」的依据：`query` 没召回，或召回的摘要全对不上且最高置信度偏低，或 `list` 返回 `found:false`。

报「暂时不可用」时，**不代表没有**，别因此就去联网。报错带「服务说明」时，按说明做（多久后重试、继续等、改用别的方式）；没有说明就稍后重试一次。这些都在你这边处理，不跟玩家提知识库。

## 库里没有时：联网补充

联网只补充当前缺少的文字事实与含义；图片请求由素材取图技能按自己的来源顺序处理。已有的名称、平台与来源共享，足够回答当前问题时停止搜索。搜索用「无畏契约 + 已核实名称或玩家原话 + 缺少的方面」，手游加「手游」。

1. **筛**：只采用靠得住的说法——官方渠道（官网、官方账号、游戏内文本）、主流百科与 wiki，或几个互不相干的来源说法一致。来源不明、只有一处孤证、像营销号洗稿或 AI 拼凑、和官方设定或彼此矛盾、说的其实是别的游戏、低俗不当的内容，都不采用。
2. **用**：采用的内容可以写进 `game_knowledge`，只作本次参考，不与库内知识混写。
3. **说**：先用平常话告诉玩家这个你还没学过，再讲网上的说法，并点明是网上看到的、不一定准，请玩家对一下是不是他想要的。
4. **筛完一条不剩**：按下节「没查到」的说法处理，不用印象补。

回复只讲采用了的内容，像本来就只看到这些一样往下说。

## 玩家的叫法

国服环境：回复使用本次知识结果、资产记录、官方页面或可靠联网来源核实的国服官方中文名；确认前沿用玩家原话的叫法。`query` 保留玩家原话检索，由召回原文确认实体和正式名。`alias` 的本地对照只作为检索线索，不作为语义证据。

## 需要图片时关联素材取图

玩家同时需要图片时，调用 `无畏契约素材取图`，共享已确认的对象、国服名、平台、图片类型与来源。已命中的知识路径可作为 `--knowledge-id` 保留；明确的素材 uuid 可直接用于取图。资产技能根据自己的候选和图片证据完成选图，不重复查询已有信息。

当前文字知识已够用时就停止本技能；仅为取图而存在的名称、款式和视觉核对，留在资产技能。涉及社区梗的意义或设定尚不清时，在这里补文字证据，信息足够后回到玩家任务。

知识服务报错按本技能重试规则处理；素材检索结果只证明资产字段与图片，不替代梗含义或设定的文字证据。

## 不要让玩家看到

玩家不知道有这套资料，也不用知道它长什么样。

- 回复和思考里都不要提：资料、查询、检索、条目、编号、「没查到」，也不要提命令名。网上搜来的内容是例外：照上节的说法点明出自网上。
- 不要提这套资料的样子：分了哪些页、每个英雄有几部分、一共多少内容、怎么分类。
- 库里查到的内容当作你本来就懂：直接说「捷风是银白短发、青蓝配色」，不说出处，不贴原文，不报数量。
- 库里和网上都没有某个角色、技能或梗的可靠内容时，如实告诉玩家这部分你不确定，不编造特征、技能描述、配色；缺了它不影响出图、但会影响准确性时，说一声。说法里不带查的过程（不说「资料里没有」「没查到」），例如：「这个英雄的具体配色我不太确定，先按你给的图来画，你看有哪里不对再改」。缺关键信息时，像设计师一样直接问玩家想做哪个英雄、什么风格。
- 用了查到的内容的回复，发出去之前先检查：`python3 <valorant-perler 技能目录>/scripts/val_perler.py search guard --text "<要发的话>"`，被拦（退出码 2）就按提示改写再发。
